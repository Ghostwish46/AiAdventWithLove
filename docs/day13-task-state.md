# День 13: состояние задачи (Task State Machine)

Формализованный конечный автомат задачи работает как **always-on слой** поверх любой стратегии контекста (Sliding Window, Sticky Facts, Branching, Memory Layers).

## Три измерения состояния

| Поле | Описание |
|------|----------|
| **Этап** | `planning` → `execution` → `validation` → `done` |
| **Текущий шаг** | Что делаем прямо сейчас |
| **Ожидаемое действие** | Что должно произойти дальше |

Дополнительно: цель задачи (`taskGoal`), список выполненных шагов (`completedSteps`).

## Как это работает

1. При каждом сообщении пользователя LLM-классификатор (`classifyTaskStateUpdate`) обновляет состояние задачи.
2. Если задача активна, в system prompt добавляется блок `--- СОСТОЯНИЕ ЗАДАЧИ ---`.
3. После каждого успешного хода состояние сохраняется в `Conversation.taskStateJson`.
4. При повторном открытии чата состояние восстанавливается — агент продолжает с той же точки **без повторных объяснений**.

**Явной кнопки «Пауза» нет.** «Пауза» = пользователь ушёл из чата (главный экран, другой чат, закрыл приложение). При возврате всё на месте.

## Сборка промпта

```
[system]
Базовый промпт
--- ПЕРСОНА АССИСТЕНТА --- (если выбрана)
... (стратегия контекста: факты / память / и т.д.)
--- СОСТОЯНИЕ ЗАДАЧИ ---
Этап: execution (выполнение)
Текущий шаг: ...
Ожидаемое действие: ...
...

[user/assistant — окно сообщений по стратегии]
```

## Как проверить

1. Запустите: `./gradlew :desktopApp:run` или Android.
2. «Новая тема» → любая стратегия → «Начать диалог».
3. В сводке диалога смотрите панель **«Состояние задачи»**.

### Сценарий: ТЗ на MVP доставки

| # | Действие | Ожидание |
|---|----------|----------|
| 1 | «Нужно ТЗ на MVP доставки, бюджет 2 млн, срок 3 месяца» | Панель: ● Planning, шаг «Сбор требований». Агент уточняет scope |
| 2 | Несколько уточнений (аудитория, фичи) | Шаг и «ожидание» обновляются |
| 3 | «План готов, пиши структуру ТЗ» | ● Execution. Агент выдаёт черновик |
| 4 | **Уход** — на главный экран или закрытие app | `taskStateJson` сохранён |
| 5 | Открыть тот же чат | ● Execution, тот же шаг, история на месте |
| 6 | «Продолжай детализацию функционала» | Агент продолжает без «напомните задачу» |
| 7 | «Проверь полноту ТЗ» → финал | ● Validation → ● Done |

### Сравнение со Sliding Window без task state

| Ситуация | Без task state | С task state |
|----------|----------------|--------------|
| Вернулись через день | Модель опирается на последние 8 реплик | Этап, шаг и цель зафиксированы в system prompt |
| «Продолжай» | Может переспросить контекст | Продолжает с `expectedAction` |
