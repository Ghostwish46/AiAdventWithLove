# День 11: модель памяти ассистента (memory layers)

Реализована явная **трёхслойная модель памяти** как стратегия `MEMORY_LAYERS`. Стратегии Дня 10 (Sliding Window, Sticky Facts, Branching) сохранены для сравнения.

## Три слоя памяти

| Слой | Назначение | Хранение | Жизненный цикл |
|------|-----------|----------|----------------|
| **Краткосрочная** | Текущий диалог — последние 8 реплик | In-memory, восстанавливается из `Conversation.messages` | Только текущая сессия |
| **Рабочая** | Цель, ограничения, решения **текущей задачи** | `Conversation.workingMemoryJson` | Per-chat, сбрасывается в новом чате |
| **Долговременная** | Профиль, предпочтения, устойчивые знания | `long_term_memory.json` (глобально) | Между всеми чатами |

## Явный роутинг

Класс `MemoryRouter` определяет правила:

1. **Каждая реплика** → краткосрочная память (автоматически).
2. **Рабочая память** — LLM-классификатор (`classifyMemoryUpdate`) при каждом сообщении пользователя: цели, ограничения, статус задачи.
3. **Долговременная память** — если:
   - пользователь пишет триггер: «запомни», «запиши в профиль», «на будущее»;
   - нажимает кнопку **«В долговременную»** (иконка закладки) на сообщении;
   - LLM помечает запись как профиль / предпочтение / устойчивое знание.
4. **routingLog** — массив строк с объяснением, куда и почему попала каждая запись (виден в UI).

## Сборка промпта

```
[system]
Базовый промпт
--- РАБОЧАЯ ПАМЯТЬ (текущая задача) ---
...
--- ДОЛГОВРЕМЕННАЯ ПАМЯТЬ ---
...

[user/assistant — только краткосрочное окно, 8 реплик]
```

## Как проверить

1. Запустите приложение: `./gradlew :desktopApp:run` или Android.
2. «Новая тема» → выберите **Memory Layers** → «Начать диалог».
3. В сводке диалога смотрите панель **«Слои памяти»** и **«Последний роутинг»**.

### Сессия 1 (Memory Layers)

| Шаг | Сообщение | Ожидаемый слой |
|-----|-----------|----------------|
| 1 | «Я Android-разработчик, предпочитаю Kotlin и краткие ответы.» | **longTerm** (профиль) |
| 2 | «Нужно ТЗ на доставку еды, бюджет 2 млн, MVP 3 месяца.» | **working** (задача) |
| 3–12 | Уточнения (аудитория, платформы, фичи, ограничения) | **shortTerm** + обновление **working** |
| 13 | «Сформулируй итоговое ТЗ списком разделов.» | Ответ учитывает **working**, даже если шаги 2–5 выпали из окна |

## Таблица: данные → слои → влияние

| Данные | Слой | Видно в UI | Влияет на ответ |
|--------|------|------------|-----------------|
| Последние 8 реплик | Краткосрочная | Да | Тон, уточнения «только что сказанное» |
| Бюджет, цель ТЗ, ограничения MVP | Рабочая | Да | Итоговое ТЗ в конце сессии 1 |
| «Я Android-разработчик, Kotlin» | Долговременная | Да | Ответ о стеке в сессии 2 |
| Ручной pin (закладка на сообщении) | Долговременная | Да + routingLog | Сохраняется между чатами |

## Ожидаемое поведение

- **Краткосрочная:** модель «забывает» реплики старше 8 сообщений, но видит их в UI.
- **Рабочая:** бюджет, сроки, ограничения остаются в system-блоке на протяжении чата.
- **Долговременная:** профиль переносится в новый чат; рабочая память — нет.
- **routingLog:** после каждого сообщения пользователя показывает явное решение роутера.
